Benchmark v2.0 · node-level localisation

Did the aligner find the right place on the page?

For every node of the document tree, the benchmark asks which regions of which pages that node occupies — and whether the aligner found them. Where it has no trustworthy answer of its own, it declines to grade rather than guess.

modulebenchmark_v2_0/ goldnode → {regions} | ABSENT metricarea IoU ≥ 0.5 inputson-disk cache, no inference

Three decisions that define it

Everything else follows from these. Each one is a deliberate trade, and each one is why a particular kind of wrong answer cannot slip through unnoticed.

the unit

A whole node, not a word.

Grading runs at the granularity a reader cares about: select a paragraph in the tree, light up the right part of the page. A node is judged once, on where it landed.

the answer

A set of regions, or none at all.

Nodes routinely span several regions, across columns or pages, so the answer is a set. ABSENT — the node is on no page — is a real answer that a method can get right or wrong.

the refusal

Ungradeable nodes are dropped, not failed.

Where the benchmark has no dependable answer of its own, it removes the node from scoring entirely. Every judgement it does keep carries the provenance of where it came from.

The whole pipeline

Where everything comes from

The benchmark itself runs no models. It reads four artefacts off disk, each produced earlier by a different component, and knowing which is which is what tells you how far a result can be trusted.

the four inputs and what produced them
ArtefactProduced byWhat it contributes
ast.json Mistral OCR, model mistral-ocr-latest, called through the Files API. Its per-page Markdown is parsed into the typed tree by app/ast_builder.py. The inventory of nodes and their text. Everything the benchmark grades is a node from here.
paragraph.json PP-DocLayoutV3 region detection, run through PaddleOCR on pages rendered at 200 dpi by pypdfium2. Region text is aggregated from PP-OCRv5 detection and recognition lines. The regions themselves — the vocabulary of places a node can be said to occupy, on both sides of the comparison.
the word stream No model. pypdfium2 reads the PDF’s own embedded text layer at 200 dpi, giving each word its box directly from the file. The evidence linking node text to page coordinates. The only part of the gold that no model can bias.
annotations.json You, working the three queues in /annotate. Verdicts are written per item as you go. The human and audited tiers — the only judgements that override the automatic proposal.

And the methods being graded

positional aligner Flattens both sides to normalised character streams and diffs them with Python’s difflib.SequenceMatcher. No model, no training — but it depends on the recovered reading order being right.
order-free aligner Embeds node text and region text with the sentence-transformer all-MiniLM-L6-v2 and scores every pair by cosine similarity, keeping matches at or above 0.5. Order is ignored entirely.
reading order A reimplementation of XY-Cut++ in layout/reading_order.py: pure geometry over region boxes and their labels, so no model and no text. Feeds the positional aligner only — the gold never uses it.
What a result is therefore conditional on

The gold is independent of both aligners, which is what makes the comparison fair. It is not independent of the two upstream models: the node inventory comes from Mistral OCR, and the regions come from PP-DocLayoutV3. A node the OCR model never emitted cannot be missed, and a region the detector never found cannot be occupied. Only the word coordinates, taken from the PDF’s own text layer, are free of model influence.

Two practical notes for reproducing a number. mistral-ocr-latest is a moving alias, so a rerun months apart may not parse to the same tree; pin a dated model if a figure needs to survive. And the corpus is ten born-digital arXiv papers — resnet, attention, bert, vgg, faster-rcnn, adam, vit, unet, densenet, batchnorm — all of them clean, single-source PDFs with real text layers, which is the friendliest possible setting for the word-stream evidence above.

Building the gold

The gold answers one question per node: which regions of which pages does this node occupy? The answer is a set of region keys, or the sentinel ABSENT meaning the node appears nowhere on any page — which is a real and useful answer, not a missing one.

The automatic proposal, and its one strict rule

Steps 1–3 are bookkeeping: find each node’s text among the words the PDF already carries, mark those words as owned, and collect the words that fall inside each detected region. Step 4 is where the design decision sits.

Three queues, three different repairs

Your verdicts in /annotate don’t merely correct the proposal; each queue fixes a distinct way it fails.

excluded:<node> For nodes the proposal could not place at all. You either name the regions outright or declare the node absent from every page.
audit:<node> Accept or reject a proposal. Accepting promotes it to the audited tier; rejecting removes the node from the gold entirely rather than replacing it with a guess.
null:<region> For regions holding ownerless words. Either it is furniture, or it belongs to a node the proposal missed — an assignment extends that node’s gold rather than replacing it.

Every entry carries its provenance

Each node’s gold is tagged with the tier it came from — human, then audited, then unreviewed oracle — and every report prints the composition. That is what lets the benchmark run before annotation is finished without quietly passing off unverified gold as verified. Each node also gets a kind (prose, heading, formula, table, image, marker) read from its own text, because the AST’s own types are too coarse to show where a method actually struggles.

The part that matters most: what is deliberately not scored

Four cases are dropped rather than counted wrong — a node the proposal couldn’t place, one whose proposal you rejected, one that dominates no region, and unclaimed regions labelled table or formula, where a word-level procedure is structurally blind.

The alternative would be to record “this node belongs nowhere” and score against it. That quietly punishes an aligner for succeeding where the automatic procedure failed, and the resulting error is systematic: it falls hardest on formulas, tables and figures, exactly the material that separates one method from another. Dropping those nodes keeps the measurement honest at the cost of coverage, so thin gold before annotation is the expected state rather than a fault.

3

What a method predicts

An aligner returns a reverse map from each region to a ranked list of candidate owner nodes. Scoring keeps only the primary owner, then inverts it into node → {predicted regions}. That mirrors exactly how the viewer colours a region, so the benchmark grades what a user actually sees — at the cost of discarding secondary owners, which is a real limitation worth stating in the paper.

Scoring, and why by area

Both region sets are rasterised into per-page occupancy masks at quarter-pixel resolution and compared as intersection over union. A node counts as localised at IoU ≥ 0.5.

mean IoUAverage overlap, which separates “just cleared the bar” from “nailed it”.

Reading a run honestly

  • Check the tier line first. Every run prints how much of the gold is human, audited, or unreviewed. A headline number resting mostly on the third tier is a provisional number.
  • --human-only is the trustworthy mode. It restricts scoring to human-tier gold — and right now will grade very few nodes, until the annotation pass is further along.
  • Watch the n in the by-kind table. The per-kind columns are the most useful diagnostic and the most easily over-read; formula and table rows stay thin until their queues are annotated.
  • Nodes pool, not documents. Corpus figures weight every node equally, so a long document pulls harder than a short one.
