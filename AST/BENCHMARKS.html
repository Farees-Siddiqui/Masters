V1.0Token attribution against text-layer gold

A born-digital PDF secretly contains a perfect record: every character and its exact position on the page. Neither OCR engine (Mistral on the AST side, Paddle on the box side) can influence it, so it acts as a neutral referee. v1 turns that record into an answer key, one word at a time.

1 · Tokenizetext layer → words with positions
→
2 · Place nodesfind each node's text in the stream
→
3 · Predictaligner box claims → per-word owners

4 · Comparetwo dicts, entry by entry

Step 1 — a "word" is ink at a location, not a string

oracle.extract_tokens reads every page into Token records. Real one from resnet:

Token(page=1, index=201, text='where',
      bbox=(492.0, 1351.4, 557.3, 1370.8),   # pixel rectangle on page 1
      stream_start=1330, stream_end=1335)    # slice of the document stream
key = '1:201'                              # "page 1, word #201" — its identity
page, index
Which page, and the word's position in that page's text layer. Together they form the key — every table below is keyed by it, which is why the 492 copies of "the" in resnet never collide: each is a separate physical object.
bbox
Pixel rectangle (x0, y0, x1, y1) at 200 dpi, top-left origin — the union of the word's per-character boxes reported by pdfium.
stream_start / stream_end
The word's slice of the stream: all words joined into one normalized (lowercased, ligature-folded) string, 59,147 chars for resnet. The stream exists so node text can be searched; the slice is the bridge back from text position to page position.

Step 2 — build the answer key by placing whole nodes

Each AST node's full text is searched for in the stream — never word by word. A 200-character paragraph occurs exactly once, so its common words ride along inside a rare context:

placements = {
  'n2': (0, 44),      # stream[0:44] = 'deep residual learning for image recognition'
  'n3': (45, 91),     # 'kaiming he xiangyu zhang shaoqing ren jian sun'
  'n1': (4219, 4257), # 'arxiv:1512.03385v1 …' — the vertical sidebar, found
}                       #   late in the PDF's internal order, as it should be

Every token overlapping a placed span inherits that node. Tokens nobody claims get None — the NULL class (page numbers, text inside figures):

token_gold = {
  '1:0':   'n2',    # 'Deep'  → title node
  '1:328': None,    # '0' — a tick label inside a figure; belongs to nobody
}
# 'the' appears 492×, owned by 115 different nodes — resolved by position:
#   '1:37'  (page 1, x=666)  → 'n7'      '7:212' (page 7, x=545) → 'n107'

Steps 3–4 — predict and compare

The aligner outputs reverse: for each layout box, its ranked owning nodes. Geometry (boxes_to_tokens: a token belongs to the box containing its center) turns that into a prediction with the same shape as the answer key, and scoring is literally two dicts compared entry by entry. tp / (tp + fp) — of the words the aligner assigned to a node, the fraction assigned correctly.
recall
tp / (tp + fn) — of the words that truly belong to some node, the fraction the aligner found.
F1
Harmonic mean of the two; the headline. Reported micro (tokens pooled) and macro (per-document mean) — a gap between them means one document is carrying the result.
null_accuracy
Of words truly owned by nobody, the fraction the aligner correctly left alone.
false_attribution_rate
Of words truly owned by nobody, the fraction given an invented owner — the provenance-critical error.
accuracy_up_to_ambiguity
Accuracy that forgives picking the identical twin of the right node (two headings both reading "MS COCO") — no method can tell identical texts apart, so the gap to plain accuracy is an ambiguity tax, not a defect.
n_excluded
Words deliberately not scored: regions whose AST counterpart is non-literal (tables → markdown, formulas → LaTeX), where gold-NULL means "oracle can't see", not "no owner".

The measured flaw: answer-key contamination

The oracle fails to place ~24% of nodes (LaTeX formulas, image refs, bare "1"s). Those nodes' words become gold-NULL — so when an aligner correctly matches them, it gets punished. Caught live on resnet:

token '3:360' = 'Here'
  gold: None                # oracle couldn't place n43 — it contains LaTeX
  pred: 'n43'  'here $\mathbf{x}$ and $\mathbf{y}$ are the input…'
                            # the aligner is RIGHT, and gets charged a false attribution

458 of 477 scored "false attributions" on resnet predicted a node
the oracle itself failed to place — 96% contamination.

The fix (July 2026): a gold-NULL word whose predicted node is unplaced is now excluded (n_excluded_unverifiable) instead of scored. Corpus impact, 10 docs:

V2.0Node localization against human gold

v2 flips the hierarchy: the unit is the AST node — the thing a user actually clicks — and the gold is a plain asserted relation, not an inference:

gold(node) = {box keys}   # e.g. gold('n43') = {'3:10'} — asserted, checkable in 2s by eye
           | ABSENT       # the node appears on no page

Where gold comes from — three tiers, strongest wins

human
Verdicts from the /annotate tool, stored in layout_output/<doc>/annotations.json. The excluded queue asserts boxes for nodes the oracle never placed — formulas, tables, images: exactly v1's blind spot. The NULL queue confirms furniture or assigns missed owners.
audited
Oracle placements a human accepted in the audit queue (fuzzy placements served first). Rejects drop the node from gold entirely.
oracle
Unreviewed oracle proposals, converted to boxes by majority ownership: a box joins a node's gold only when that node owns >50% of the box's owned tokens. Included so the benchmark runs before annotation finishes — but every report prints the tier composition, so a result resting on tier 3 says so.

Scoring — area, not identity

Prediction: the aligner's primary owner per box, inverted to pred(node) = {boxes}. A node is localized when the pixel area of its predicted boxes overlaps its gold boxes at IoU ≥ 0.5 (intersection-over-union of the two regions' areas). Area is the comparison so granularity can't game it: if gold says one box and the aligner claims the same region as two half-boxes, the areas agree and the node counts as found.

localization_accuracy
Fraction of gold nodes localized (IoU ≥ 0.5). The thesis sentence: "the stream aligner correctly localizes 97.5% of nodes."
mean_iou
Average IoU over gold nodes — how tight the matches are, not just whether they cleared the bar.
n_exact
Nodes whose predicted box set equals gold exactly (IoU = 1 by definition).
n_missed
Nodes with gold boxes for which the aligner predicted nothing at all.
absent_accuracy
Of nodes a human marked ABSENT, the fraction the aligner correctly left unmatched.
false_claim_rate
Of furniture boxes (owned by nobody — human-confirmed, or oracle-inferred outside its blind labels), the fraction some node wrongly claimed. v2's version of false attribution, at box grain.
by_kind
Everything broken down by content class recognized from the node text: prose · heading · formula · table · image · marker. This is the row that says what to work on next.

Two things this output demonstrates. First, legibility: both aligners localize 97.5% of nodes, but stream plants half as many false flags on furniture — a finding v1's pooled F1 never surfaced. Second, honesty: "18% verified" and "formula n=2" say plainly that most gold is still unreviewed and the hard cases are thin — because the formulas sit in the excluded queue, waiting for clicks. Annotation directly grows the benchmark.

The relationship between v1 and v2

They share one pipeline. v1's oracle machinery now plays two roles: diagnostic tier (when v2 says "formulas fail", v1 shows which words leaked where) and proposal generator (its placements, with per-placement ratio/exact provenance, are what humans confirm in the audit queue). The annotation you do for v2 simultaneously measures v1's oracle error rate.
