The DeepSeek-OCR survival guide

Getting pages, boxes, and markdown out of DeepSeek's OCR model — the one Unlimited-OCR grew out of — without fighting the pins.

DeepSeek-OCR (October 2025) is a ~3B vision-language OCR model and the direct predecessor of Baidu's Unlimited-OCR. Its real thesis is contexts optical compression: a DeepEncoder (SAM-base + CLIP-large with a 16× convolutional squeeze, ~380M params) turns a full page into as few as 64–400 vision tokens, and a DeepSeek-3B-MoE decoder (~570M active params) decodes the document back out of them. A page of text that would cost thousands of text tokens goes in as a few hundred vision tokens — around 97% decoding precision below 10× compression, degrading to roughly 60% at 20×. For you, that thesis has a practical payoff: it reads dense pages fast, and it tells you where everything was.

1 · Setup and your first parse

The model card pins an older stack than Unlimited-OCR's, and the pins matter — the trust_remote_code inference code was written against them:

pip install torch==2.6.0 transformers==4.46.3 tokenizers==0.20.3 \
    einops addict easydict pymupdf
# flash-attn==2.7.3 is the documented backend — Linux-only in practice.

Don't try to reuse an Unlimited-OCR env: the remote code imports LlamaFlashAttention2, which transformers removed after 4.46 — on 4.57.1 the model fails at load (verified). Make a separate venv with the pins; don't downgrade the shared one. On Windows, skip flash-attn and load with _attn_implementation='eager'.

import torch
from transformers import AutoModel, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained('deepseek-ai/DeepSeek-OCR', trust_remote_code=True)
model = AutoModel.from_pretrained('deepseek-ai/DeepSeek-OCR', trust_remote_code=True,
                                  use_safetensors=True,
                                  _attn_implementation='flash_attention_2')  # or 'eager'
model = model.eval().cuda().to(torch.bfloat16)

model.infer(
    tokenizer,
    prompt='<image>\n<|grounding|>Convert the document to markdown. ',
    image_file='your_image.jpg',
    output_path='out/',
    base_size=1024, image_size=640, crop_mode=True,  # gundam mode
    save_results=True,
)

Same rule as Unlimited: the prompts are fixed strings the model was trained on. Copy them exactly — including the trailing space, and note the \n after <image>, which Unlimited's prompt doesn't have.

2 · The prompts

PromptWhat you get
<image>\n<|grounding|>Convert the document to markdown. Layout-aware markdown with bounding boxes for every block
<image>\nFree OCR. Plain text, no layout markup, no boxes
<image>\nParse the figure. Structured parse of a chart/figure crop
<image>\nLocate <|ref|>xxxx<|/ref|> in the image. Bounding box for a specific string

The <|grounding|> token is the interesting one. With it, the raw stream wraps every block in reference/detection spans:

<|ref|>text<|/ref|><|det|>[[x1, y1, x2, y2]]<|/det|>

Coordinates are normalized to a 0–1000 grid on each axis — multiply by width/1000 and height/1000 to get pixels. save_results=True does the bookkeeping for you: it writes result.mmd (markdown with the grounding spans stripped), result_with_boxes.jpg (the page with boxes drawn on), and crops of detected figures into images/.

3 · The five resolution modes

Resolution is the compression knob, and it's explicit — each mode has a fixed vision-token budget:

ModeParametersVision tokensUse for
tinybase_size=512, image_size=512, crop_mode=False64Slides, sparse pages
smallbase_size=640, image_size=640, crop_mode=False100Books, clean reports
basebase_size=1024, image_size=1024, crop_mode=False256General documents
largebase_size=1280, image_size=1280, crop_mode=False400Dense single pages
gundambase_size=1024, image_size=640, crop_mode=Truedynamic (n×100 + 256)Newspapers, very dense layouts

Gundam mode tiles the page into local 640-px crops on top of a 1024-px global view, so the token count scales with how much is on the page. Start with base or small for ordinary documents; reach for gundam when text is small and dense. The ~10× compression sweet spot means most pages decode near-perfectly from a few hundred tokens — that's the whole trick.

4 · PDFs: loop, don't batch

There is no infer_multi here — that's Unlimited-OCR's addition. Each call is one image, so a PDF is rasterize-then-loop, and anything that spans a page break (a table continued overleaf) will come out split. Rasterize at 300 DPI with PyMuPDF exactly as for Unlimited, then:

pages = pdf_to_images('document.pdf')   # same recipe as the Unlimited guide
for i, page in enumerate(pages, 1):
    model.infer(tokenizer,
                prompt='<image>\n<|grounding|>Convert the document to markdown. ',
                image_file=page, output_path=f'out/page_{i:04d}',
                base_size=1024, image_size=640, crop_mode=True,
                save_results=True)

Note what's missing versus Unlimited: no max_length=32768 ceiling to chunk around (each page is its own context) and no documented no_repeat_ngram_size guard. Decoding loops are rarer per-page than in a 30-page context, but they still happen on pathological tables; if a page loops, re-run just that page in a lower mode.

5 · Serving it for real

The repo's production path is vLLM — the released code ships run_dpsk_ocr_pdf.py and friends, and the model card quotes ~2,500 output tokens/s on an A100-40G for concurrent PDF processing. vLLM has since merged native support, so recent versions load deepseek-ai/DeepSeek-OCR directly. That's the route for throughput; the Transformers path above is for experiments.

6 · What it's actually good at

On OmniDocBench, DeepSeek-OCR beats GOT-OCR2.0 (which spends 256 tokens per page) while using only 100, and beats MinerU2.0 (~6,000+ tokens per page) while staying under 800. The honest summary:

  • Great fit: bulk document ingestion, LLM training-data pipelines, anything where tokens-per-page is the cost that matters — and, unlike Unlimited, anything needing spatial grounding, since every block comes with a box.
  • Poor fit: maximum-fidelity parsing of a single precious document — a mode chosen too low silently drops precision; Unlimited's multi-page context also stitches cross-page structures this model can't.
  • Bonus: ~100 languages, and the figure-parse prompt reads charts into structure.

Cheat sheet

  • Prompts are fixed strings — exact copy, trailing space and \n included.
  • <|grounding|> = markdown + boxes; Free OCR. = plain text. Boxes are 0–1000 normalized.
  • Five modes; token budget is the knob. Base/small for clean pages, gundam for dense ones.
  • PDFs: 300 DPI, loop pages — no infer_multi, cross-page tables split.
  • Pins are old (transformers 4.46.3 / torch 2.6.0) — separate venv if the remote code balks; eager attention on Windows.
  • Serving: vLLM, natively supported in recent versions.
Sources: github.com/deepseek-ai/DeepSeek-OCR, huggingface.co/deepseek-ai/DeepSeek-OCR, the DeepSeek-OCR paper (arXiv:2510.18234). Verify against the repo before depending on details — this model line moves fast.
