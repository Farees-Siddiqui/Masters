The Unlimited-OCR survival guide

Getting real documents out of Baidu's Unlimited-OCR without your GPU, your patience, or your output toppling over.

Unlimited-OCR is Baidu's 3B vision-language OCR model, a successor to DeepSeek-OCR. Instead of the classic detect → recognize → layout pipeline, it takes an image — or a whole stack of pages — and emits the parsed document in one pass, up to 32,768 tokens of it. This guide goes from one image to a batch API.

1 · Setup and your first parse

Tested stack: Python 3.12, CUDA 12.9. It's a 3B model in bf16 (~6 GB of weights), so plan on a 12 GB+ GPU — CPU is not an option you'd enjoy.

pip install torch==2.10.0 torchvision==0.25.0 transformers==4.57.1 \
    Pillow einops addict easydict pymupdf psutil matplotlib

The model ships its own inference code (hence trust_remote_code=True); the weights download from the Hub on first load:

import torch
from transformers import AutoModel, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained('baidu/Unlimited-OCR', trust_remote_code=True)
model = AutoModel.from_pretrained('baidu/Unlimited-OCR', trust_remote_code=True,
                                  use_safetensors=True, torch_dtype=torch.bfloat16)
model = model.eval().cuda()

model.infer(
    tokenizer,
    prompt='<image>document parsing.',
    image_file='your_image.jpg',
    output_path='out/',
    base_size=1024, image_size=640, crop_mode=True,  # "gundam" mode
    max_length=32768,
    no_repeat_ngram_size=35, ngram_window=128,
    save_results=True,
)

Two things to know: the prompt '<image>document parsing.' is a fixed string the model was trained on — copy it exactly. And save_results=True writes the parsed output to output_path for you.

2 · The two modes

ModeParametersUse for
gundambase_size=1024, image_size=640, crop_mode=TrueSingle images, dense pages
basebase_size=1024, image_size=1024, crop_mode=FalseMulti-page / PDFs

Gundam mode adds cropped local views on top of the global one — that's what reads small, dense text. Base mode is one straight pass per page, cheaper when you're feeding it thirty of them. Rule of thumb: gundam for a single image, base for a document.

3 · Multi-page documents and PDFs

Don't loop infer() over pages — infer_multi puts all pages in one context, so tables and paragraphs that span page breaks come out whole:

model.infer_multi(
    tokenizer,
    prompt='<image>Multi page parsing.',  # exact wording, again
    image_files=['page1.png', 'page2.png', 'page3.png'],
    output_path='out/',
    image_size=1024,  # base mode
    max_length=32768,
    no_repeat_ngram_size=35, ngram_window=1024,
    save_results=True,
)

max_length=32768 caps the entire output — if a dense document cuts off mid-parse, you hit it. Split into chunks of pages and call again.

PDFs need rasterizing first; the repo's recipe uses PyMuPDF at 300 DPI:

import os, tempfile
import fitz  # PyMuPDF

def pdf_to_images(pdf_path, dpi=300):
    doc = fitz.open(pdf_path)
    tmp_dir = tempfile.mkdtemp(prefix='pdf_ocr_')
    mat = fitz.Matrix(dpi / 72, dpi / 72)
    paths = []
    for i, page in enumerate(doc):
        out = os.path.join(tmp_dir, f'page_{i+1:04d}.png')
        page.get_pixmap(matrix=mat).save(out)
        paths.append(out)
    doc.close()
    return paths

4 · The repetition knobs

OCR models are pathologically prone to decoding loops — documents are full of legitimately repetitive content (table rows, repeated headers), and 30,000 tokens in, the model is one bad step from emitting the same row forever. no_repeat_ngram_size=35, ngram_window=… blocks any 35-gram that already appeared in the recent window. It's 35 (not the chat-model's usual 4) so that legitimate short repetition in tables survives.

These aren't quality knobs, they're crash guards. Keep the documented values. Symptoms only: stuck in a loop → widen ngram_window; repetitive tables getting corrupted → raise no_repeat_ngram_size.

5 · Serving it for real

For throughput beyond experiments, run an inference server. Easiest is the prebuilt vLLM image — an OpenAI-compatible endpoint out of the box:

docker pull vllm/vllm-openai:unlimited-ocr        # default (CUDA 13.0)
docker pull vllm/vllm-openai:unlimited-ocr-cu129  # Hopper GPUs

SGLang takes more setup (a custom wheel from the repo) but adds streaming and server-side logit control:

python -m sglang.launch_server \
    --model baidu/Unlimited-OCR \
    --attention-backend fa3 \
    --context-length 32768 \
    --mem-fraction-static 0.8 \
    --enable-custom-logit-processor \  # REQUIRED: enforces the no-repeat guard
    --disable-overlap-schedule

Then the repo's batch client fans out a directory or PDF against the server:

python infer.py --pdf ./document.pdf --output_dir ./outputs \
    --concurrency 8 --image_mode gundam

Pick by need: Transformers for experiments, vLLM for an easy endpoint, SGLang for streaming and decoding control.

6 · What it's actually good at

On llamaindex/ParseBench: mean 46.17, text content 86.81, text formatting 0.97. That spread is the honest summary:

  • Great fit: full-text extraction, search indexing, RAG ingestion — anywhere the words matter and the markup doesn't.
  • Poor fit: faithful formatting reconstruction, precise table structure.
  • Not provided: bounding boxes / word coordinates. If you need spatial grounding, pair it with a separate layout detector.

Cheat sheet

  • Prompts are fixed strings — copy them exactly.
  • Gundam for single images, base for documents.
  • PDFs: rasterize at 300 DPI with PyMuPDF first.
  • Output truncated? You hit max_length=32768 — chunk the pages.
  • Looping output? Widen ngram_window. Corrupted tables? Raise no_repeat_ngram_size.
  • Serving: vLLM docker for easy, SGLang for control (don't forget --enable-custom-logit-processor).
Sources: github.com/baidu/Unlimited-OCR, huggingface.co/baidu/Unlimited-OCR. Verify against the repo before depending on details — this model line moves fast.
