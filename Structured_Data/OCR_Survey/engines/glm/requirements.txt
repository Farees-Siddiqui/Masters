# GLM-OCR (zai-org/GLM-OCR) -- isolated venv for the OCR survey.
#
#   python3 -m venv OCR_Survey/engines/glm/.venv
#   OCR_Survey/engines/glm/.venv/bin/pip install -r OCR_Survey/engines/glm/requirements.txt
#
# Two load-bearing choices, both verified on this box rather than assumed:
#
# 1. torch comes from the **cu126** index. CUDA 13 dropped Volta, so a cu13x
#    build has no sm_70 kernels and the Tesla V100s would be unusable. Verified:
#    torch.cuda.get_arch_list() includes sm_70, all 4 GPUs visible.
#
# 2. transformers must be >= 5.3 for `GlmOcrForConditionalGeneration`
#    (model_type `glm_ocr`). Confirmed present in 5.14.1, so no
#    trust_remote_code is needed. NOTE: this is the same transformers 5.x line
#    that broke LayoutLMv3's processor in ../../../Layout/ -- that is exactly why
#    this engine gets its own venv and must never share one with DeepSeek-OCR
#    (pinned 4.46.3) or Unlimited-OCR (4.57.1).
#
# Runtime note recorded for provenance: the model's native dtype is bfloat16,
# but Volta has no bf16 tensor cores. Measured here on a 4096x4096 matmul:
# fp16 1.56 ms, bf16 14.00 ms, fp32 9.70 ms. We load in **float16** -- 9x faster
# than bf16, at the cost of a small numeric deviation from the released weights.
# FlashAttention-2 needs Ampere+, so attention stays sdpa/eager.
